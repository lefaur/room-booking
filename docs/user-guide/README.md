# Инструкции для пользователей

Инструкции для сотрудников офиса: что нажать и что они увидят. Пишутся словами экрана (см.
[словарь](glossary.md)), каждый снимок снят автотестом на живом стенде — инструкция не расходится с
системой, пока сценарии съёмки зелёные.

| Инструкция | Для кого | Сценарий съёмки |
|---|---|---|
| [Бронирование переговорок и рабочих мест](booking.md) | сотрудник | `tests/features/instructions/booking.feature` |

[Словарь](glossary.md) · [Вопросы к постановке](questions.md) — что нашлось при съёмке и выглядит
нелогично.

## Как сделаны снимки

Сценарий съёмки — обычный behave-сценарий с тегом `@instruction`: готовит данные (этаж «Офис, 2 этаж»,
переговорки «Москва», «Питер», сотрудник «Анна Смирнова»), проходит процесс теми же шагами, что
автотесты, и на нужном экране делает снимок с красной рамкой вокруг того, о чём строка инструкции:

```gherkin
Когда в браузере выбирают на карте "Питер"
Тогда снимок «room-panel» с рамкой вокруг элемента "booking-panel"
```

Рядом со снимком пишется текст экрана (`reports/instructions-text/<снимок>.txt`): надписи в инструкцию
берутся оттуда дословно. Не нашлась рамка — снимок всё равно делается, в логе WARNING.

В обычный прогон сценарии съёмки не входят и идут строго по одному (одно название этажа на всех,
чужая бронь не должна попасть в кадр).

## Переснять

Стенд поднят (`docker compose up -d --wait`), из корня репозитория:

```bash
docker compose run --rm -v ./docs:/docs -e INSTR_DIR=/docs/user-guide/img tests sh run.sh -t @instruction
```

Снимки перезапишутся в `docs/user-guide/img/`; `git diff --stat` покажет, какие экраны изменились.
Без `-v ./docs:/docs` снимки лягут в `reports/instructions/`, docs не тронутся.

Пишет и обновляет инструкции навык Claude `user-guide` (`.claude/skills/user-guide/`), см.
[CLAUDE.md](../../CLAUDE.md).
