# Архитектура учебной мишени (черновик)

Цель: приложение, на котором видно всё, что умеет тестировать AQA: API, UI на разных экранах, роли, асинхронные цепочки через очередь, письма, фоновые джобы, внешнюю интеграцию, гонки, адаптивность.

Название: **OfficeSpace** — бронирование переговорных и рабочих мест в офисе.

## Сервисы (docker compose)

| Сервис | Стек | Что делает |
|---|---|---|
| `web` | Vue 3 + Vite + TypeScript, nginx | Сайт для сотрудников и админка. Адаптивная вёрстка (телефон, планшет, десктоп) |
| `auth` | FastAPI | Регистрация, вход, JWT (access + refresh с ротацией), роли и права, журнал входов |
| `booking` | FastAPI | Этажи, комнаты, рабочие места, карта этажа, брони, проверка доступности, правила и лимиты |
| `notifier` | Python worker | Читает события из брокера, строит письма по шаблонам, отправляет по SMTP |
| `tgbot` | FastAPI + поток опроса Bot API + потребитель RabbitMQ | Уведомления о бронях, подтверждение, отмена и чек-ин кнопками, команда `/my`. Привязка аккаунта по одноразовому коду |
| `scheduler` | FastAPI + APScheduler | По расписанию вызывает внутренние джобы сервисов (`/internal/jobs/*` с сервисным токеном). В стенде режим `manual`: джобы запускает тест через API |
| `stubs` | FastAPI, состояние в памяти | Заглушки внешних систем: Telegram Bot API и производственный календарь. Тесты управляют ими через `/_control/*` |
| `db` | PostgreSQL 16 | Отдельные схемы `auth` и `booking` |
| `rabbitmq` | RabbitMQ 3 (с management), отдельный контейнер | Брокер сообщений между сервисами: обменник событий, очереди `notifier` и `tgbot`, очередь недоставленных. Тесты смотрят очереди через management API |
| `mailpit` | Mailpit | Тестовый SMTP: письма видны в веб-интерфейсе и через API. Тесты читают письма |
| `gateway` | nginx | Единая точка входа: `/` → web, `/api/auth` → auth, `/api/booking` → booking |

## Предметная область

- **Этаж** (floor): план в виде SVG-координат.
- **Ресурс** (resource): либо `room` (переговорка), либо `desk` (рабочее место). Поля: название, вместимость, координаты на плане, оборудование (проектор, доска), признак активности.
- **Бронь** (booking):
  - комната — по времени, слотами по 30 минут, до `max_booking_hours` часов;
  - рабочее место — на целые дни, до `max_desk_days` подряд;
  - статусы `pending` → `confirmed` → `checked_in` / `cancelled`; `expired`; `no_show`.
- **Подтверждение** в течение `confirm_timeout_minutes`, иначе бронь просрочена.
- **Чек-ин** по кнопке в день брони (иначе `no_show` и ресурс освобождается).
- **Выходные и праздники**: из внешнего календаря. На нерабочие дни рабочие места бронировать нельзя.

## Роли и права

| Роль | Права |
|---|---|
| `employee` | свои брони, просмотр карты |
| `manager` | брони отдела, отмена чужих, отчёты |
| `facility` | ресурсы, этажи, настройки правил |
| `admin` | всё, управление ролями и пользователями |

Права задаются каталогом (`bookings.read_all`, `resources.write`, `users.manage` и т. д.), у роли набор прав. Пользователь без нужного права получает 403.

## Авторизация

- JWT: access (15 минут) и refresh (7 дней, ротация, семейства токенов, повторное использование отзывает семейство).
- Выход отзывает refresh. «Забыл пароль» всегда отвечает одинаково. Ограничение частоты запросов на вход.

## События (RabbitMQ)

`booking.created`, `booking.confirmed`, `booking.cancelled`, `booking.expired`, `booking.reminder`, `user.registered`, `user.password_reset`, `telegram.linked`. Публикуются в обменник RabbitMQ. `notifier` превращает события в письма, `tgbot` — в сообщения Telegram. Сообщения, которые не удалось обработать, уходят в очередь недоставленных. Тесты проверяют не только API, но и «событие → письмо в Mailpit», «событие → сообщение в тестовый Telegram API».

## Джобы (`scheduler`)

1. Просрочка неподтверждённых броней.
2. Напоминание за 30 минут до брони.
3. Автоосвобождение: нет чек-ина через 15 минут от начала.
4. **Парсинг производственного календаря** (выходные, праздники) с внешнего источника (в тестах это `calendar-stub`).
5. Ночная чистка устаревших токенов.

## Карта этажа

SVG: комнаты и рабочие места нарисованы по координатам, цвета показывают занятость на выбранный день и время. Клик по объекту открывает форму брони.

**Редактор карты для администратора** (право `floors.write`): создать этаж, загрузить подложку (SVG или картинку), перетаскивать и менять размер комнат и мест, добавлять и удалять объекты, задавать названия, вместимость, оборудование, активность. Сохранение через API с проверкой пересечений и выхода за границы плана; параллельная правка двумя админами ловится версией (409). Тесты Playwright проверяют перетаскивание, сохранение и то, что обычный пользователь видит изменения.

## Что даёт для демонстрации тестирования

- API-тесты с ролями и правами, JWT (просрочка, ротация, повторное использование refresh).
- Гонки: два параллельных запроса на одну и ту же комнату или место.
- Асинхронные цепочки: событие в брокере → письмо в Mailpit → ссылка из письма; событие → сообщение бота (бот в тестах ходит в подменный Telegram API).
- Брокер: очереди, недоставленные сообщения, повторная доставка, идемпотентность обработчиков.
- Джобы: управление временем и состоянием БД, проверка результата.
- Внешняя интеграция: подмена источника календаря и проверка поведения при его сбое.
- UI: адаптивная вёрстка на трёх размерах экрана, карта, админка, формы, ошибки.
- Прямые проверки в PostgreSQL, группы конфигов (глобальные настройки правил), параллельный запуск.
